# slnmix + petari セキュリティ説明資料(情報システム部門向け)

社内で承認済みのチャット AI(Microsoft 365 Copilot Chat など)を使って開発するための
2 つのコマンドラインツール、slnmix と petari の導入審査用の資料です。
どのデータがどこへ出るか、ツールが何をして何をしないかを、コードで確かめられる形でまとめます。

- 対象: slnmix 0.20.0 / petari 0.12.0(2026-10-11 時点)
- ソース: <https://github.com/ishibashi0112/slnmix> / <https://github.com/ishibashi0112/petari>
- ライセンス: どちらも MIT

## 1. 要約

| 観点 | 回答 |
|---|---|
| 外部への通信 | 実行時はしない。通信するのはインストール時の npm レジストリだけ(§3) |
| AI に渡るデータ | 利用者が自分でチャット画面に貼り付け・添付したものだけ。送り先は社内で承認済みのチャット AI で、ツールが新しい送り先を増やすことはない(§2, §4) |
| AI の権限 | ない。AI は PC 上でコマンドを実行できず、ファイルにも直接触れない |
| 書き込む範囲 | プロジェクトのフォルダの中だけ。slnmix は出力ファイルと初期設定を書き、petari は AI の変更を書く。petari は外へのパス・シンボリックリンク経由の書き込みを拒否する(§5, §7) |
| 依存パッケージ | slnmix は 12 パッケージ(すべて MIT、インストールスクリプトなし)。petari は実行時依存ゼロ(§8) |
| 起動する外部コマンド | クリップボード・レジストリ参照・git などの OS コマンドと、利用者が `slnmix build` を実行したときの MSBuild だけ。いずれもシェルを通さない(§6) |

## 2. データの流れ

1. 利用者が開発 PC で `npx slnmix` を実行する。slnmix はソースを読んで 1 つのテキスト
   (パック)にまとめ、プロジェクト直下のファイルとクリップボードに出す
2. 利用者がブラウザでチャット AI を開き、パックを本文に貼る(大きいときは添付する)。
   **PC の外へデータが出るのはこの操作だけ**
3. チャット AI が、変更内容を changes.md というテキスト(どのファイルのどこをどう変えるか)で返す
4. 利用者が changes.md をダウンロードし、`npx petari` を実行する(または常駐中の
   `petari watch` が拾う)。petari は形式とパスを検証してから、プロジェクトのファイルを書き換える
5. 利用者が git diff で変更を確認してから、ビルド・テストを実行する

slnmix と petari は通信しません(§3)。AI が PC 上で何かを実行する経路もありません。

## 3. 外部への通信

- **slnmix**: ネットワークを扱うモジュール(http / https / net / tls / dgram / dns)と
  fetch を一切使っていません
- **petari**: 外への通信はありません。唯一、差分表示(`petari show`)で VS Code が無い
  とき(または `--browser` 指定時)に限り、ブラウザで差分を見るための HTTP サーバーを **127.0.0.1(自分の PC 内)の
  空きポート**で一時的に開きます。URL に 128 ビットの乱数トークンが必要で、
  Host / Origin の検証、CSP による外部リソースの遮断を行い、30 分操作がなければ止まります。
  エディタ(Monaco Editor、Microsoft、MIT)はパッケージに同梱しており、CDN から読み込みません
- **インストール時**: `npx slnmix` / `npx petari` は初回に npm レジストリ
  (registry.npmjs.org)からパッケージを取得します。社内レジストリ(ミラー)経由にする、
  または版数を固定して導入する方法は §8 を参照してください

確かめ方(ソースを取得して実行):

```sh
grep -rnE "from ['\"](node:)?(https?|net|tls|dgram|dns)['\"]|require\(['\"](https?|net|tls|dgram|dns)['\"]\)|fetch\(" slnmix/src petari/src
```

slnmix は該当なし、petari は差分表示サーバー(`src/infra/diff-server.ts`)と
そのページ内の自分自身への保存リクエストだけが出ます。

## 4. AI に渡るデータと、その制御

### 4.1 パックに入るもの

slnmix は `.sln` / `.vbproj`(Visual Studio のプロジェクト定義)を解析し、
**ビルド対象として登録されているソース**を 1 つのテキストにまとめます。ディレクトリを
丸ごと走査することはしません。例外は、設定ファイル `slnmix.config.json` で明示した
ディレクトリと、新しい形式(SDK スタイル)の `.vbproj` が既定でビルド対象にする
プロジェクトフォルダ内の `*.vb` だけです。

- 入るもの: ビルド対象のソース、`docs/` の設計書・仕様書・引継ぎ書、作業手順と出力規約の文
- 入らないもの: `.gitignore` / `.repomixignore` に一致するファイル、バイナリ、
  画面デザイナーの自動生成ファイル(コントロール構成の要約だけを入れる)。
  除外したファイルは理由付きでパック内に一覧されます
- 注意: `.vbproj` がプロジェクトの外(別ドライブなど)のファイルを参照している場合は、
  そのファイルも入ります(ビルドに使われるため)

### 4.2 認証情報の自動マスク

パスワード・ユーザー ID・API キー / トークン・秘密鍵らしき文字列リテラルと、
接続文字列の `Password=` などの値を、既定で `[MASKED]` に置き換えます。
ランダムな英数字列(高エントロピー値)も既定で伏せます。置き換えた件数は実行時に表示され、
パックのヘッダーには AI 向けに伏せ字であることを明記します。

これは名前と形からの推定であり、すべての秘密情報を見つけられる保証はありません。
秘密情報をソースに書かない運用は引き続き必要です。無効化オプション(`--no-mask`)は
ありますが、既定は有効です。

### 4.3 クリップボード

slnmix は実行の最後に、チャットに貼るもの(パック全体、または大きいときは指示文だけ)を
クリップボードに入れます。Windows の**クリップボードの履歴**や**デバイス間の同期**が
有効だと、その内容が履歴に残る・同期されることがあります。

- グループ ポリシー(コンピューターの構成 > 管理用テンプレート > システム > OS ポリシー)の
  クリップボードの履歴(Allow Clipboard History)と、デバイス間のクリップボードの同期
  (Allow Clipboard synchronization across devices)で無効にできます
- ツール側では `npx slnmix --no-clip` でクリップボードを使わない運用にできます
  (この場合は出力ファイルを開いてコピーします)

### 4.4 チャット AI 側でのデータの扱い

送信したデータがチャット AI のサービス内でどう扱われるか(保存・学習への利用の有無など)は、
そのサービスの契約と設定(例: Microsoft 365 Copilot Chat のエンタープライズ データ保護)に
よります。slnmix と petari の範囲外です。社内で承認済みのサービスとアカウントで使ってください。

## 5. AI の回答を反映するときの安全弁(petari)

petari は changes.md の内容を**実行しません**。テキストとして解析し、ファイルの書き換えにだけ使います。

- **形式の検証**: 規約の形式に合わないものは何も書き込まずにエラーにする
- **全部か無しか**: 変更のうち 1 か所でも当てられなければ、何も書き込まない
- **パスの制限**: 絶対パス・`..`・UNC パス・ドライブ文字・`~`・代替データストリーム(`:`)・
  Windows の予約デバイス名を拒否する。シンボリックリンク経由でプロジェクトの外を指す
  書き込みも拒否する
- **履歴と巻き戻し**: 書き換え前後の内容を `.petari/history/` に保存し、`petari undo` で戻せる
- **二重適用の防止**: 同じ changes.md をもう一度当てようとすると止まる
- **文字コードの保全**: Shift_JIS / UTF-8 / 改行コードを元のまま保ち、変更していない行のバイト列は変えない
- **端末出力の無害化**: AI 由来の文字列に含まれる制御文字・双方向制御文字を取り除いてから表示する

`petari watch` は、ダウンロードされた changes.md を確認なしで当てる常駐モードです。
上の検証はすべて同じように効きます。書き込みはプロジェクトのフォルダ内に限られ、
`petari undo` で戻せます。

**AI が書いたコードが PC 上で動くのは、利用者がビルド・テストを実行したとき**です
(`slnmix build` もビルドを実行します)。.vbproj のビルドイベントのように、プロジェクトの
定義に書かれた処理はビルドの時点で動くため、AI が .vbproj / .sln を変えたときは特に差分を確認してください。
そのため、ビルドの前に git diff で変更を確認する運用を前提にしています(運用ガイドの手順も
この順です)。

## 6. 起動する外部コマンド

どちらのツールも、外部コマンドは引数を配列で渡して起動し、シェル(cmd / sh)を通しません。
PowerShell に渡すパスは単一引用符でエスケープしています。

| ツール | コマンド | いつ | 目的 |
|---|---|---|---|
| slnmix | `powershell`(Set-Clipboard)/ `pbcopy` / `xclip` | `npx slnmix` の最後 | 貼るものをクリップボードへ入れる(`--no-clip` で止まる) |
| slnmix | `node`(petari の `init`) | `npx slnmix init` のときだけ | petari の初期設定を作る |
| slnmix | `vswhere.exe` / `MSBuild.exe` | `npx slnmix build` のときだけ | Visual Studio に付属する MSBuild を探してビルドする(`--msbuild` で場所を指定できる) |
| petari | `reg query` | 引数なしの `petari` / `petari watch` | ダウンロードフォルダの場所を調べる(OneDrive へのリダイレクト対応) |
| petari | `git status --porcelain` | 適用の前 | 未コミットの変更があれば警告する |
| petari | `powershell`(Get-Clipboard / Set-Clipboard)/ `pbpaste` / `pbcopy` / `xclip` | `--clip` 指定時 / 失敗時 | changes.md の読み取り、失敗レポートのコピー(設定で止められる) |
| petari | `code --diff` | `petari show` | VS Code で差分を開く(コマンド名か絶対パスのみ許可) |
| petari | `Start-Process` / `open` / `xdg-open` | `petari show` で VS Code が無いとき | 差分レポートを既定のブラウザで開く |

PowerShell の実行が制限されている環境では、クリップボードへのコピーが警告付きで失敗します。
出力ファイルはそのまま使えるので、手でコピーする運用に戻せます。

## 7. PC に残るファイル

| ファイル | 内容 | 扱い |
|---|---|---|
| `repomix-output.xml` / `repomix-output.prompt.md` | パック(コードを含む)と指示文 | プロジェクト直下。`slnmix init` が `.gitignore` に追加する |
| `.petari/history/` | 書き換え前後のファイルと changes.md の原本 | プロジェクト直下。`.gitignore` に追加される。件数の上限は設定(`historyLimit`)で決められる |
| 一時ファイル(slnmix) | Windows でクリップボードへ渡すためのテキスト、`slnmix build` のエラーのログ | `%TEMP%` に作り、使い終わったらすぐ削除する |
| 一時ファイル(petari) | ブラウザ表示用の差分レポート(HTML) | `%TEMP%` に作り、次の `petari show` の実行時に 1 時間より古いものを削除する |

## 8. 依存パッケージとサプライチェーン

**petari** は実行時依存がゼロです(Node.js の標準機能だけで動く)。ブラウザ差分表示用の
Monaco Editor はビルド時にパッケージへ同梱しています。

**slnmix** の実行時依存は次の 12 パッケージで、すべて MIT ライセンス、
インストール時に実行されるスクリプト(preinstall / install / postinstall)はありません
(2026-10-11、slnmix 0.20.0 のロックファイルで確認)。

| パッケージ | 用途 |
|---|---|
| fast-xml-parser 5.10.1(と依存の @nodable/entities, fast-xml-builder, is-unsafe, path-expression-matcher, strnum, anynum, xml-naming) | `.sln` / `.vbproj` の XML 解析 |
| iconv-lite 0.7.3(と依存の safer-buffer) | Shift_JIS のソースの読み取り |
| ignore 7.0.6 | `.gitignore` の判定 |
| petari 0.11.0 以上 | `slnmix init` で petari の初期設定を呼ぶため |

npm の版数指定は範囲(`^`)のため、`npx` で都度取得すると依存の版がその時点の最新に
なることがあります。審査した版で固定したい場合は、次のいずれかを推奨します。

- 社内の npm レジストリ(ミラー)に審査済みの版だけを置き、そこから取得する
- `npm install -g slnmix@0.20.0 petari@0.12.0` のように版数を指定して導入し、
  更新は審査の上で行う(依存の版はインストールした時点で決まり、その後は変わりません)
- ソースを取得して `pnpm install --frozen-lockfile` でロックファイルどおりに入れ、
  ビルドしたものを配布する

公開パッケージの中身は `npm pack slnmix@0.20.0` / `npm pack petari@0.12.0` で
取得して確認できます。

## 9. Claude Code / Codex などのエージェント型ツールとの違い

| 観点 | エージェント型ツール | slnmix + petari |
|---|---|---|
| コードの送り先 | ツールの提供元の API(新しい送り先の審査が必要) | 社内で承認済みのチャット AI(既存の送り先のまま) |
| AI の実行権限 | PC 上でコマンドの実行・ファイルの編集ができる(許可の仕組みはある) | なし。AI はテキストを返すだけ |
| 送る範囲を決めるのは | エージェントが必要に応じて読む | 利用者がパックを作って貼る(中身はファイルで確認できる) |
| 変更の反映 | エージェントが直接書き換える | petari が検証してから書き換え、履歴を残す |

## 10. 残るリスクと推奨する運用

| リスク | 対策 |
|---|---|
| AI が誤った・悪意のあるコードを書く | ビルド・テストの前に git diff で確認する。変更は `petari undo` と git で戻せる |
| AI が .vbproj / .sln のビルド定義(ビルドイベント等)を書き換え、ビルド時にコマンドが動く | .vbproj / .sln の差分は特に確認してからビルドする(petari 自身が .vbproj に足すのは新規ファイルの登録行だけ) |
| ソースや文書に紛れた指示で AI の回答が誘導される(プロンプトインジェクション) | 回答はファイルの変更としてしか反映されず、パスはプロジェクト内に限られる。上と同じく差分を確認する |
| 認証情報のマスク漏れ | マスクは推定のため、秘密情報をソースに置かない。機密度の高い案件ではパックの中身を確認してから送る |
| クリップボードの履歴・同期 | グループ ポリシーで無効にするか、`--no-clip` で運用する(§4.3) |
| チャット AI 側でのデータの扱い | 承認済みのサービス・アカウントでのみ使う(§4.4) |
| 依存パッケージの更新による混入 | 版数の固定・社内レジストリでの配布(§8) |

## 11. 他のチャット AI で使う場合

ツール側は特定のチャットサービスに依存していません。次の条件を満たすサービスなら同じ流れで使えます。

- 長いテキストを本文に貼れる(slnmix は約 12 万文字を目安にしています)か、ファイルを添付できる
- 回答のテキストをファイルとしてダウンロードできる、またはコピーできる
  (コピーしたものは `petari --clip` でクリップボードから適用できます)

実際の動作を確かめているのは Microsoft 365 Copilot Chat です(添付ファイル内の指示が
無視される・空行が落ちるなどの癖に合わせた調整は、そのサービスでの実測に基づきます)。
